## 3. 正式程序现场验收

### 3.1 目录初始化

1. 创建一个新用户；
2. 确认 `storage/{user_id}/` 下存在 exe、dll、mesh、Forward_data、staging、archives；
3. 对比用户 exe/dll 与 manifest SHA-256；
4. 管理后台执行工作区检查；
5. 期望检查结果为正常。

### 3.2 启动参数和工作目录

使用 Process Explorer 或等价工具观察进程：

- [ ] Image Path 为 `storage/{user_id}/DCR_3D.exe`
- [ ] Current Directory 为 `storage/{user_id}/`
- [ ] Command Line 不含参数文件、输入文件或任务目录参数
- [ ] `libiomp5md.dll` 从用户根目录加载

### 3.3 连续任务和历史归档

1. 同一用户提交 A、B 两个输入；
2. 确认 B 只能在 A 归档成功后进入准备；
3. A、B 均结束后检查两个 UTC+task ID 归档；
4. 确认 A 归档仍为 A 输入和结果；
5. 确认固定工作区为 B 最近现场；
6. 从页面下载 A、B ZIP，核对嵌套目录和文件摘要。

### 3.4 全终态归档

分别制造：

- [ ] 正常完成
- [ ] 非零退出
- [ ] 超时
- [ ] 排队取消
- [ ] 运行取消
- [ ] 管理员终止
- [ ] 程序启动失败
- [ ] 工作区准备失败
- [ ] 服务重启中断

每项确认：任务先进入归档状态，正式归档完整出现后才进入业务终态。

### 3.5 归档失败保护

1. 临时移除 archives 写权限或模拟磁盘错误；
2. 结束当前任务；
3. 确认任务为归档失败、工作区现场未被覆盖；
4. 再提交同用户任务，确认不启动；
5. 恢复权限后人工重试；
6. 确认原任务归档成功，后续任务才可启动。

### 3.6 程序升级

1. 更新统一模板的 exe、dll、version 和 SHA-256；
2. 保持一个用户运行，另一个用户空闲；
3. 发起批量同步；
4. 确认空闲用户成功、运行用户延期；
5. 运行用户任务归档后确认自动同步；
6. 新任务详情和 task.json 应记录新版版本和摘要；
7. 旧归档不复制二进制且仍记录旧版本摘要。
