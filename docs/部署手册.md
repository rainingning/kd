# 部署手册（Windows 单机）

目标环境：一台 Windows 服务器，FastAPI、PostgreSQL、前端静态文件和 DCR_3D 同机部署。

## 1. 环境依赖

| 依赖 | 建议版本 | 说明 |
|---|---|---|
| Python | ≥ 3.11 | 后端、迁移及运维脚本 |
| PostgreSQL | ≥ 15 | 数据库、任务队列和用户工作区锁 |
| Node.js | ≥ 20 | 仅构建前端时需要 |
| `DCR_3D.exe` | 客户正式版本 | 固定路径、无参数运行 |
| `libiomp5md.dll` | 与 exe 匹配 | 必须与 exe 同目录 |

## 2. 数据库准备

```sql
CREATE DATABASE fortran_platform TEMPLATE template0;
```

若报 `collation version mismatch`，可先执行：

```sql
ALTER DATABASE template1 REFRESH COLLATION VERSION;
```

## 3. Python 环境

在项目根目录执行：

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r backend\requirements.txt
```

## 4. 正式程序模板

在 `program_template/programs/` 下分别创建 `dcr_3d`、`be_fetd`、`fdem3d_frequency_domain` 三个目录，完整布局见第 13 节。每个目录有独立 `program-manifest.json`。

新程序 manifest 示例：

```json
{
  "program_key": "be_fetd",
  "version": "1.0.0",
  "exe": "BE_FETD.exe",
  "dll": "libiomp5md.dll",
  "exe_sha256": "64位小写十六进制摘要",
  "dll_sha256": "64位小写十六进制摘要",
  "parameter_sha256": {
    "GroundedWireSource.dat": "64位小写十六进制摘要",
    "LoopSource.dat": "64位小写十六进制摘要"
  }
}
```

PowerShell 使用 `Get-FileHash <文件> -Algorithm SHA256` 逐一计算摘要。后端启动时强制校验三个模板；任一文件缺失、manifest 错误或摘要不一致时服务拒绝启动。

## 5. 环境配置

复制 `.env.example` 为 `.env`，至少修改数据库密码、JWT 密钥、目录和 SMTP：

```text
DATABASE_URL=postgresql+asyncpg://postgres:密码@127.0.0.1:5432/fortran_platform
STORAGE_ROOT=D:/fortran-platform/storage
FORTRAN_PROGRAM_TEMPLATE_DIR=D:/fortran-platform/program_template
RESULT_ZIP_CACHE_ROOT=D:/fortran-platform/storage/.zip-cache
EXECUTION_MODE=dcr3d
JWT_SECRET=生产随机长字符串
APP_BASE_URL=http://server:8000
```

关键配置：

| 配置项 | 说明 |
|---|---|
| `EXECUTION_MODE` | 生产必须为 `dcr3d`；开发联调可用 `mock` |
| `FORTRAN_PROGRAM_TEMPLATE_DIR` | 统一正式程序模板目录 |
| `STORAGE_ROOT` | 用户固定工作区和归档根目录 |
| `RESULT_ZIP_CACHE_ROOT` | Forward_data ZIP 缓存目录 |
| `MOCK_DCR3D_COMMAND` | 仅 mock 模式使用的无参数程序命令 |
| `DATABASE_URL` | PostgreSQL asyncpg 连接串 |
| `JWT_SECRET` | 生产必须替换 |
| SMTP 配置 | 开放注册和找回密码前必须完成 |

旧版带 `{params}`、`{data}` 的 `FORTRAN_COMMAND` 不再用于正式执行。

## 6. 初始化数据库和管理员

首次部署：

```bat
cd backend
..\.venv\Scripts\python -m alembic upgrade head
cd ..
.venv\Scripts\python scripts\create_admin.py admin admin@example.com --password <强密码>
```

创建管理员时会同步创建用户工作区并复制 exe/dll。模板校验失败时管理员创建失败。

## 7. 前端构建

```bat
cd frontend
npm install
npm run build
cd ..
```

产物位于 `frontend/dist/`，后端会自动托管。开发模式可使用 `npm run dev`，其 `/api` 代理到后端 8000 端口。

## 8. 启动服务

```bat
scripts\start_backend.bat
```

健康检查：

```text
GET http://127.0.0.1:8000/api/health
```

## 9. NSSM 开机自启

```bat
nssm install FortranPlatform "D:\path\to\kd\.venv\Scripts\python.exe" "-m uvicorn app.main:app --host 0.0.0.0 --port 8000"
nssm set FortranPlatform AppDirectory "D:\path\to\kd\backend"
nssm set FortranPlatform AppStdout "D:\path\to\kd\logs\backend.log"
nssm set FortranPlatform AppStderr "D:\path\to\kd\logs\backend.log"
nssm start FortranPlatform
```

## 10. 从旧任务目录升级

本版本按客户确认清空旧任务历史，不迁移旧任务结果。

### 10.1 强制前置步骤

1. 停止后端和调度器；
2. 确认没有 DCR_3D.exe 或 Mock 计算进程；
3. 使用 `pg_dump` 完整备份 PostgreSQL；
4. 完整备份 `storage/`；
5. 记录数据库和 storage 双备份位置与校验值；
6. 部署新代码；
7. 执行数据库结构升级。

```bat
cd backend
..\.venv\Scripts\python -m alembic upgrade head
cd ..
```

### 10.2 dry-run

```bat
.venv\Scripts\python scripts\migrate_workspace_layout.py
```

检查输出的用户数、任务数、通知数、活动任务数和旧任务目录清单。

### 10.3 实际执行

```bat
.venv\Scripts\python scripts\migrate_workspace_layout.py ^
  --execute ^
  --backup-reference "D:/backup/fortran-platform-20260808" ^
  --backup-checksum "备份清单SHA256"
```

脚本会：

- 拒绝在仍有活动任务时执行；
- 先原子改名隔离旧任务目录；
- 清空旧任务和任务关联通知；
- 清理旧数字任务目录；
- 保留用户、参数模板和审计日志；
- 初始化所有已有用户工作区；
- 复制并校验 exe/dll；
- 输出用户级 JSON 报告。

任一用户初始化失败都会写入报告并返回非零退出码，不会静默跳过。

### 10.4 迁移后检查

```bat
.venv\Scripts\python scripts\verify_workspaces.py --report workspace-check.json
```

全部用户 `ready=true` 后才可启动服务。

### 10.5 回滚

本次升级包含不可逆历史清理，回滚必须同时：

1. 停止新后端和全部计算进程；
2. 恢复发布前 PostgreSQL 备份；
3. 恢复同一时点的 storage 备份；
4. 切回旧代码和旧前端 dist；
5. 验证数据库、任务历史和文件一致后再恢复服务。

严禁只恢复数据库或只恢复 storage。

## 11. 真实程序验收

上线前使用客户提供的正式物料验证：

1. `model_DC.dat` 位于用户根目录；
2. 输入位于 `mesh/mesh.mphtxt`；
3. 每次运行前 `Forward_data/` 被清空并重建；
4. 进程工作目录为 `storage/{user_id}/`；
5. 命令行只有 `DCR_3D.exe`，没有参数；
6. DLL 可正常加载；
7. 成功、失败、超时和取消任务均生成归档；
8. Forward_data ZIP 内容与客户基准一致；
9. 同一用户连续任务严格串行；
10. 不同用户可在全局上限内并行。

## 12. 程序升级

1. 停止直接修改用户目录；
2. 在统一模板目录更新 exe、dll 和 manifest；
3. 确认模板摘要正确；
4. 登录管理后台“程序与工作区”；
5. 检查模板状态；
6. 发起批量同步。

空闲用户立即同步；准备、运行或归档中的用户自动延期，调度器会在其空闲后重试。同步与任务执行共用用户锁，不会在程序运行中替换文件。

## 13. 多程序目录结构

```text
program_template/programs/
├── dcr_3d/{DCR_3D.exe, libiomp5md.dll, program-manifest.json}
├── be_fetd/{BE_FETD.exe, libiomp5md.dll, GroundedWireSource.dat, LoopSource.dat, program-manifest.json}
└── fdem3d_frequency_domain/{FDEM3D_Frequency_Domain.exe, libiomp5md.dll, GroundedWireSource.dat, LoopSource.dat, program-manifest.json}

storage/{user_id}/
├── programs/
│   ├── dcr_3d/{DCR_3D.exe, libiomp5md.dll, model_DC.dat, mesh/, Forward_data/}
│   ├── be_fetd/{BE_FETD.exe, libiomp5md.dll, GroundedWireSource.dat, LoopSource.dat, mesh/, Forward_data/}
│   └── fdem3d_frequency_domain/{FDEM3D_Frequency_Domain.exe, libiomp5md.dll, GroundedWireSource.dat, LoopSource.dat, mesh/, Forward_data/}
├── staging/{task_id}/
└── archives/{UTC时间戳}_task{task_id}/
    ├── model_DC.dat                         # DCR，或下列两个新程序参数文件
    ├── GroundedWireSource.dat
    ├── LoopSource.dat
    ├── mesh/mesh.mphtxt
    ├── Forward_data/**
    ├── stdout.txt
    ├── stderr.txt
    └── task.json
```

三个固定工作区分别可被各自下一任务覆盖；历史查询和下载只读取 `archives/`。同一用户三个程序仍共享一个执行锁。

旧布局升级顺序：停止服务并完成 PostgreSQL + storage 同一时点备份，执行 `alembic upgrade head`，先运行 `scripts/migrate_multi_program_layout.py` dry-run，再使用 `--execute --backup-reference ... --backup-checksum ...` 执行迁移。

## 14. 日常运维

- **备份**：PostgreSQL 与 storage 必须作为同一备份集；
- **磁盘**：监控工作区、归档和 ZIP 缓存总量；
- **归档失败**：在管理后台“归档异常”查看原因，修复权限或磁盘后重试；
- **工作区异常**：用户管理页执行“检查工作区”和“同步程序”；
- **服务重启**：系统会终止孤儿进程并归档中断现场；
- **定期清理**：只清理超过保留期的归档、staging、ZIP 和数据库任务记录；
- **单用户并发**：固定为 1，不允许管理员调大；
- **全局并发**：根据正式任务 CPU、内存和磁盘数据评估后配置；
- **磁盘启动阈值**：管理后台 `min_free_disk_mb` 默认 1024 MB，低于阈值时任务在覆盖固定工作区前失败并归档 staging。

## 15. DCR 真实参数升级

DCR 模板目录必须包含真实默认 `model_DC.dat`，且 `program-manifest.json` 的 `parameter_sha256.model_DC.dat` 必须等于文件 SHA-256。该默认文件只用于新用户初始化和显式“载入默认”，程序同步不会覆盖用户已保存参数。

旧部署升级流程：

1. 停止服务，确认无活动任务；
2. 对 PostgreSQL 和 storage 做同一时点备份并记录校验值；
3. 执行 `alembic upgrade head`；
4. 执行 `python scripts/migrate_dcr_real_params.py` dry-run；
5. 使用 `--execute --backup-reference <引用> --backup-checksum <摘要>` 正式迁移；
6. 执行 `python scripts/verify_workspaces.py`；
7. 启动服务并检查 `/api/dcr-params/current` 和网页“DCR 参数”。

迁移器会采用已有可解析真实文件；已知旧占位 JSON 会先备份再替换为真实默认文件；未知损坏格式不会被静默覆盖。任何情况下都不修改历史 `archives/`。

## 16. BE/FDEM 真实源参数升级

BE_FETD 和 FDEM3D 模板均须包含真实 `GroundedWireSource.dat`、`LoopSource.dat`，并在 manifest 中登记摘要。BE 默认文件为 GB18030，FDEM 默认文件为 UTF-8；部署工具不得假定所有 `.dat` 都能作为 UTF-8 文本读取。

升级时在服务停止并完成同一时点数据库/storage 备份后执行：

```powershell
python scripts/migrate_source_real_params.py
python scripts/migrate_source_real_params.py --execute `
  --backup-reference <备份引用> --backup-checksum <备份摘要>
python scripts/verify_workspaces.py
```

迁移器逐一处理两个程序的两个当前文件：合法真实文件采用为当前镜像，已知占位文件备份后初始化真实默认，未知格式保留并报告。迁移器只读取历史 archive；可解析旧任务只更新数据库中的 DTO/schema/hash 标记，archive 字节不变。升级后任务提交改为按 stdin 1/2 快照当前文件，不再接受任务内 `.dat` 上传。
