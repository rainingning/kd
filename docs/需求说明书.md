## 1. 项目概述

### 1.1 背景

实验室有一个 Fortran 科学计算程序（下称"计算程序"），无状态，每次运行接收两个输入：

1. 算法参数文件（格式固定、参数集合固定且已知）
2. 输入数据文件

调用方式为命令行：

```
program.exe <参数文件路径> <数据文件路径>
```

- 计算结果**仅输出到 stdout**，运行中不产生其他文件
- 退出码 0 = 成功，非 0 = 失败

现需开发一套 Web 前端，将计算程序包装为在线服务，对外开放给研究者使用（**不开放 Fortran 源码**，用户只接触 Web 界面）。

### 1.2 目标

- 用户注册登录后，在线配置参数（表单化 + 校验）、上传输入数据、提交计算任务
- 系统按队列调度、受并发限制地启动计算程序进程，结果落盘为文件并提供下载
- 用户中心：历史任务追溯（参数快照 / 输入 / 输出 / 日志）、结果下载、账户管理、参数模板
- 管理后台：用户管理、任务/队列监控与干预、服务器资源监控、系统参数配置、审计

### 1.3 范围

- 本期包含：Web 前端 + 后端服务 + 任务调度执行 + PostgreSQL 存储 + 文件存储 + 管理后台
- 本期不包含（二期候选）：安全强化、开放 API、任务状态邮件通知、多计算节点、界面多语言（见第 9 章）

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 任务（Task） | 一次对计算程序的调用，含参数快照、输入文件、输出结果、日志、状态 |
| 运行队列 | 正在执行的任务集合，大小受"最大并发数"限制 |
| 等待队列 | 已提交但未开始的任务集合，FIFO 调度 |
| 参数模板 | 用户保存的一套命名参数配置，可复用 |

## 3. 系统总体架构

### 3.1 部署形态

- **Windows 服务器单机部署**：Web 后端、PostgreSQL、计算程序均在同一台机器
- 前端为静态 SPA，由 Nginx（或后端直接）托管，反向代理后端 API

### 3.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.11+ / FastAPI + SQLAlchemy + Alembic | 生态成熟，子进程管理与异步调度方便 |
| 任务队列 | **PostgreSQL 队列表**（`SELECT ... FOR UPDATE SKIP LOCKED`） | 几百用户 / 50 并发量级足够；Windows 单机下避免引入 Redis，减少运维组件 |
| 调度器 | 后端进程内嵌 asyncio 调度循环 | 单进程可管理 50 个子进程；架构简单，状态持久化在 PG |
| 数据库 | PostgreSQL（Windows 原生安装） | 结构化数据 + 队列 + 文件元数据 |
| 文件存储 | 服务器本地磁盘，PG 仅存路径与元数据 | 科学计算文件可能较大，磁盘直存简单可靠、可流式下载 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia | 中文社区成熟，管理后台类界面组件齐全 |
| 邮件 | SMTP（aiosmtplib），用于邮箱验证与密码找回 | 实验室提供 SMTP 账号 |
| 认证 | JWT（Bearer Token），密码 bcrypt 哈希 | 无状态，前后端分离 |
| 资源监控 | psutil | CPU / 内存 / 磁盘使用率 |

### 3.3 架构示意

```
浏览器 (Vue SPA)
   │ HTTPS/HTTP
   ▼
FastAPI 后端 ──────────────┐
   │ API 层                │
   │  ├─ 认证/用户         │
   │  ├─ 参数模板          │
   │  ├─ 任务/文件         │
   │  └─ 管理后台          │
   │ 调度器 (asyncio)      │        ┌──────────────────┐
   │  ├─ 扫描等待队列 ─────┼──────► │ PostgreSQL       │
   │  ├─ 启动子进程        │        │  users/tasks/... │
   │  ├─ 超时/取消/终止    │        └──────────────────┘
   │  └─ 定时清理          │        ┌──────────────────┐
   ▼                      └──────► │ 本地磁盘存储      │
program.exe × N (≤50)              │ storage/{uid}/   │
   stdout/stderr → 结果文件        │  {task_id}/...   │
                                   └──────────────────┘
```

### 3.4 存储目录结构

```
storage/
  {user_id}/
    {task_id}/
      params.in      # 由参数快照序列化生成的参数文件
      input.dat      # 用户上传的输入数据（原始文件名记录在 DB）
      stdout.txt     # 计算结果（程序 stdout）
      stderr.txt     # 错误输出（失败排查用）
```

## 4. 功能性需求

编号规则：FR-<模块>-<序号>。优先级：P0 = 必须有，P1 = 应当有。

### 4.1 注册与认证（AUTH）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-AUTH-01 | 开放注册：用户名 + 邮箱 + 密码，无需管理员审核。注册后账号为"待验证"状态 | P0 |
| FR-AUTH-02 | 邮箱验证：注册后发送含 token 链接的验证邮件（有效期 24h），点击后激活。**未激活不能登录** | P0 |
| FR-AUTH-03 | 用户名 + 密码登录，成功返回 JWT（默认有效期 24h，过期需重新登录） | P0 |
| FR-AUTH-04 | 忘记密码：输入邮箱 → 发送重置链接（有效期 1h）→ 设置新密码 | P0 |
| FR-AUTH-05 | 用户中心内可修改：用户名（需唯一）、登录密码（需验证旧密码） | P0 |
| FR-AUTH-06 | 管理员可重置任意用户密码（生成临时密码并展示一次，用户下次登录后应自行修改）；操作记入审计 | P0 |

### 4.2 参数配置（PARAM）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-PARAM-01 | 参数集合固定且已知，后端以参数 Schema（JSON 配置文件）描述每个参数的名称、类型、取值范围、默认值、单位、说明 | P0 |
| FR-PARAM-02 | 前端根据 Schema 渲染**表单化编辑界面**，并在前端做校验（类型、范围、必填） | P0 |
| FR-PARAM-03 | 提交时后端按 Schema 二次校验，并将参数序列化为计算程序要求的参数文件格式（格式规范由实验室提供，见 7.2） | P0 |
| FR-PARAM-04 | 参数模板：用户可保存多套命名模板（增删改查），提交任务时可从模板载入 | P0 |
| FR-PARAM-05 | 支持从历史任务"复制参数重新提交"：载入该任务的参数快照到表单，可修改后提交 | P0 |

### 4.3 数据上传（UPLOAD）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-UPLOAD-01 | 提交任务时上传输入数据文件，限制大小（默认 200MB，管理员可配） | P0 |
| FR-UPLOAD-02 | 记录原始文件名；文件保存至该任务目录 | P0 |

### 4.4 任务提交与队列（QUEUE）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-QUEUE-01 | 任务状态机：`QUEUED → RUNNING → COMPLETED / FAILED / CANCELED`；失败原因（崩溃/超时/被管理员终止/服务重启）记录在 `error_message` | P0 |
| FR-QUEUE-02 | FIFO 调度：等待队列按提交时间先进先出 | P0 |
| FR-QUEUE-03 | 并发限制：同时 RUNNING 的任务数 ≤ 最大并发数（默认 **50**，管理员可配） | P0 |
| FR-QUEUE-04 | 单用户限制：同一用户 RUNNING ≤ 3（可配）、QUEUED ≤ 3（可配）；超出排队上限时拒绝提交并提示 | P0 |
| FR-QUEUE-05 | 全局等待队列不设硬性上限（由单用户排队上限间接控制） | P0 |
| FR-QUEUE-06 | 用户可取消自己 QUEUED 状态的任务（直接从队列移除） | P0 |
| FR-QUEUE-07 | 用户可取消自己 RUNNING 状态的任务（终止对应进程），状态记为 CANCELED | P0 |
| FR-QUEUE-08 | 最长运行时间限制（默认 60 分钟，管理员可配），超时自动终止进程，状态记 FAILED，原因"超时" | P0 |
| FR-QUEUE-09 | 服务重启恢复：启动时将残留的 RUNNING 任务标记为 FAILED（原因"服务重启中断"），QUEUED 任务保留继续排队 | P0 |

### 4.5 任务执行（EXEC）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-EXEC-01 | 调度器将参数快照序列化为 `params.in`，以子进程方式执行 `program.exe params.in input.dat`，工作目录为该任务目录 | P0 |
| FR-EXEC-02 | stdout 重定向到 `stdout.txt`（即计算结果文件），stderr 重定向到 `stderr.txt` | P0 |
| FR-EXEC-03 | 进程退出后按退出码判定：0 → COMPLETED；非 0 → FAILED，保留 stderr 供下载排查 | P0 |
| FR-EXEC-04 | 记录排队时间、开始时间、结束时间、耗时、退出码 | P0 |
| FR-EXEC-05 | 每次任务保存完整快照：参数内容（JSON + 序列化文件）、输入文件、输出文件、stdout/stderr 日志 | P0 |

### 4.6 任务历史与结果（HISTORY）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-HIST-01 | 任务列表：本人全部历史任务，展示状态、提交时间、开始/结束时间、耗时、原始输入文件名 | P0 |
| FR-HIST-02 | 任务详情：参数快照（可读展示）、状态、时间、退出码、失败原因 | P0 |
| FR-HIST-03 | 下载：结果文件（stdout.txt）、stderr.txt、输入文件、参数文件 均可随时下载 | P0 |
| FR-HIST-04 | 任务状态为**被动获取**：列表/详情页前端定时轮询（默认 5 秒）+ 手动刷新，不使用 WebSocket 推送 | P0 |
| FR-HIST-05 | 运行中任务显示已运行时长；排队中任务显示队列位置（前面还有几个任务） | P1 |

### 4.7 站内通知（NOTIFY）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-NOTIFY-01 | 任务终态产生站内通知：COMPLETED（完成）、FAILED（含超时、崩溃）、被管理员终止 | P0 |
| FR-NOTIFY-02 | 通知列表 + 未读数标记，可标记已读；不做邮件通知 | P0 |

### 4.8 管理后台（ADMIN）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-ADMIN-01 | 仪表盘：注册用户数、当前活跃用户数（有 RUNNING 任务的去重用户数）、RUNNING 任务数、排队任务数、服务器 CPU/内存/磁盘使用率 | P0 |
| FR-ADMIN-02 | 运行中任务列表：任务 ID、用户、开始时间、已运行时长；可对单个任务执行**终止**（杀进程） | P0 |
| FR-ADMIN-03 | 等待队列查看：任务 ID、用户、提交时间、排队时长 | P0 |
| FR-ADMIN-04 | 用户管理：列表查询（按用户名/邮箱搜索、分页）、创建用户、编辑（用户名/邮箱/角色）、禁用/启用、删除（级联删除其任务与文件） | P0 |
| FR-ADMIN-05 | 重置用户密码（见 FR-AUTH-06） | P0 |
| FR-ADMIN-06 | 系统参数配置（界面化修改，即时生效）：最大并发数、单用户运行上限、单用户排队上限、任务超时时间、结果保留天数、上传大小上限 | P0 |
| FR-ADMIN-07 | 审计日志：管理员敏感操作留痕——创建/编辑/删除/禁用用户、重置密码、终止任务、修改系统参数；记录操作人、动作、对象、明细、时间；可查询分页 | P0 |
| FR-ADMIN-08 | 被禁用的用户不能登录；其排队中任务取消，运行中任务继续跑完或一并终止（默认：排队取消、运行中不动） | P1 |

### 4.9 数据清理（CLEANUP）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-CLEAN-01 | 定时任务（每日）清理超过保留期（默认 30 天，可配）的任务：**任务记录与对应文件一并删除** | P0 |
| FR-CLEAN-02 | 清理动作写入后端日志（删除任务数、释放空间） | P1 |

## 5. 非功能性需求

| 类别 | 需求 |
|---|---|
| 性能 | 支持 50 个并发计算子进程；API 常规操作响应 < 1s（不含文件上传/下载） |
| 可靠性 | 任务状态全部持久化于 PG，服务重启不丢任务（见 FR-QUEUE-09）；子进程异常不导致后端崩溃 |
| 可配置性 | 第 4 章所有"可配"项集中于 `system_config` 表，管理后台可改，无需重启 |
| 易用性 | 全中文界面；表单有校验提示；失败任务给出明确原因 |
| 可观测性 | 后端运行日志（调度事件、任务状态迁移、异常）；审计日志（管理员操作） |
| 安全基线 | 本期虽不做安全强化，但保留最低基线：密码 bcrypt 哈希、ORM 参数化查询防 SQL 注入、上传大小限制、JWT 过期、普通用户仅能访问本人数据。公网开放前建议补 HTTPS、限流、进程隔离等（见第 9 章） |
| 时区 | 数据库统一存 UTC，前端按浏览器本地时区显示 |

## 7. 外部依赖与接口约定

## 9. 本期不做 / 二期候选

- 安全强化：HTTPS、登录限流、进程隔离（低权限运行/cgroup 等效机制）、输入文件内容安全检查
- 对外开放 API（脚本化提交）
- 任务状态邮件通知
- 多计算节点 / 分布式调度（届时可再评估引入 Redis/RabbitMQ）
- 界面多语言（本期仅中文）
- 结果在线可视化
