# 研发任务分解（WBS）

> **基线文档提示：** 用户固定工作区、无参数 DCR_3D 调用和全终态归档的后续任务，以《用户独立工作区与任务归档改造研发计划.md》为准。

- 版本：v1.0
- 用途：指导本系统的逐步实现。每个任务含目标、关键产出、验收标准、依赖关系，按阶段顺序执行。
- 对应文档：《需求说明书.md》（需求编号 FR-XXX-NN 在此引用）

## P0 — 前置准备

### T0.1 实验室输入收集【阻塞项，人工】
- 目标：拿到开发必需的外部输入
- 清单：
  1. 参数清单与文件格式规范 + 样例参数文件（需求 7.2）
  2. 样例输入数据文件
  3. 真实 `program.exe`（可晚于 P5，先用 Mock）
  4. SMTP 服务器/账号/授权码（P3 前需要）
- 验收：以上物料归档到 `docs/vendor/`

### T0.2 开发环境准备
- 目标：Windows 开发机就绪
- 内容：Python 3.11+、PostgreSQL（含创建库 `fortran_platform`）、Node.js 20+、Git 仓库初始化、`.gitignore`
- 验收：`python --version`、`psql -l`、`node -v` 正常；空仓库可提交

### T0.3 Mock 计算程序
- 目标：在真实 exe 就绪前支撑全流程联调（需求 7.4）
- 产出：`mock/mock_program.py`，行为：读取参数文件与数据文件 → 按参数文件中的 `mock_sleep`（秒）睡眠模拟计算 → stdout 打印模拟结果 → 按参数 `mock_exit_code` 退出（默认 0）
- 验收：命令行 `python mock/mock_program.py params.in input.dat` 行为符合上述约定

## P1 — 后端骨架（依赖 P0）

### T1.1 FastAPI 骨架与配置

- 验收：`uvicorn` 启动，`/api/health` 返回 200；配置全部来自环境变量/`.env`

### T1.2 数据库模型与迁移
- 目标：实现需求第 6 章全部表
- 产出：`models.py`、Alembic 初始化 + 首个 migration、`system_config` 默认值写入 seed
- 验收：`alembic upgrade head` 后 7 张表（users / email_tokens / param_templates / tasks / system_config / notifications / audit_logs）结构与索引齐全

### T1.3 测试基座
- 产出：pytest + httpx AsyncClient + 独立测试库（`fortran_platform_test`）的 conftest
- 验收：`pytest` 可跑通一个健康检查用例

## P2 — 认证与用户模块（依赖 P1；FR-AUTH-01~05）

### T2.1 注册 + 邮箱验证
- 产出：`routers/auth.py`：`POST /api/auth/register`（创建 pending 用户、生成 verify token、发邮件）、`GET /api/auth/verify?token=`
- 验收：注册后收到验证邮件（可用 SMTP 调试工具代收）；未验证登录返回 403；点击链接后激活可登录

### T2.2 登录 / JWT / 当前用户
- 产出：`POST /api/auth/login` 返回 JWT；`security.py` 密码哈希与 token 签发/校验；`deps.py` `get_current_user` / `require_admin`
- 验收：错误密码 401；有效 token 可访问 `GET /api/auth/me`；禁用用户登录被拒

### T2.3 忘记密码 / 重置
- 产出：`POST /api/auth/forgot-password`（发 reset 邮件）、`POST /api/auth/reset-password`
- 验收：重置链接 1h 内有效且一次性；重置后旧密码失效

### T2.4 账户自助管理
- 产出：`PUT /api/users/me`（改用户名，查重）、`PUT /api/users/me/password`（验旧密码）
- 验收：用户名冲突 409；改密后旧密码不可登录

## P3 — 参数 Schema 与模板（依赖 P1；FR-PARAM-01/03/04）

### T3.1 参数 Schema 定义与序列化器
- 产出：`param_schema/schema.json`（依据 T0.1 的规范编写；规范未到先用占位参数集 + 明确 TODO）、`param_schema/serializer.py`：校验（pydantic 动态模型）+ 序列化为计算程序参数文件格式
- 验收：单元测试覆盖——合法参数生成字节级正确的参数文件；越界/缺参/类型错误返回结构化错误信息
- 依赖：T0.1 第 1 项（未就绪时用 Mock schema 先行，接口不变）

### T3.2 参数模板 CRUD
- 产出：`routers/templates.py`：列表/创建/更新/删除，创建与更新时走 T3.1 校验
- 验收：同一用户模板名唯一；非法参数被 422 拒绝

## P4 — 任务核心：提交、调度、执行（依赖 P2、P3；FR-QUEUE-01~09、FR-EXEC-01~05、FR-UPLOAD）

### T4.1 任务提交 API
- 产出：`POST /api/tasks`（multipart：参数 JSON + 输入文件）：校验参数 → 检查单用户排队上限 → 落盘 `params.in` 与输入文件 → 写 `tasks`（QUEUED）
- 验收：超排队上限 429；超上传大小 413；成功后返回任务 ID；文件按 3.4 目录结构落盘

### T4.2 调度器 dispatcher
- 产出：`scheduler/dispatcher.py`：FastAPI 启动时起的 asyncio 循环（1s 周期）：`SELECT ... FOR UPDATE SKIP LOCKED` 按 `queued_at` FIFO 取任务，满足 ①全局 RUNNING < max_concurrent ②该用户 RUNNING < 上限 时启动
- 验收：集成测试——提交 6 个任务（并发上限临时调 2），验证严格 FIFO、全局与单用户限额生效

### T4.3 执行器 runner
- 产出：`scheduler/runner.py`：`asyncio.create_subprocess_exec` 起 exe，stdout/stderr 重定向到文件；看门狗计时，超时 terminate→kill；正常/异常退出按退出码写终态、耗时、exit_code；写 notifications
- 验收：Mock 程序验证——成功任务 COMPLETED 且 stdout.txt 有内容；mock_exit_code=1 → FAILED 且 stderr.txt 保留；mock_sleep 超超时阈值 → FAILED(超时)

### T4.4 取消与终止
- 产出：`POST /api/tasks/{id}/cancel`（QUEUED→CANCELED；RUNNING→杀进程→CANCELED）；调度器维护 `task_id → subprocess` 注册表
- 验收：取消排队任务立即生效；取消运行中任务，Mock 长睡眠任务被杀、文件齐全

### T4.5 重启恢复
- 产出：后端启动钩子：残留 RUNNING → FAILED("服务重启中断") 并通知
- 验收：跑长任务中途 kill 后端，重启后任务状态正确

## P5 — 任务查询、下载、通知（依赖 P4；FR-HIST、FR-NOTIFY）

### T5.1 任务列表与详情
- 产出：`GET /api/tasks`（分页、按状态过滤）、`GET /api/tasks/{id}`（含参数快照、队列位置、已运行时长）
- 验收：仅能看本人任务；排队位置计算正确

### T5.2 文件下载
- 产出：`GET /api/tasks/{id}/files/{kind}`（kind ∈ result/stdout / stderr / input / params），流式返回，权限校验
- 验收：四种文件可下载；越权访问他人文件 403/404

### T5.3 站内通知
- 产出：`GET /api/notifications`（含未读数）、`POST /api/notifications/read`
- 验收：任务完成/失败/被终止均产生通知；标记已读生效

### T5.4 从历史复制参数重新提交
- 产出：前端功能为主；后端确认任务详情返回的 `params` 可直接作为 `POST /api/tasks` 入参
- 验收：用历史任务的 params 原样提交成功

## P6 — 管理后台 API（依赖 P4；FR-ADMIN-01~08）

### T6.1 仪表盘统计
- 产出：`GET /api/admin/dashboard`：注册用户数、活跃用户数、RUNNING/QUEUED 任务数、psutil CPU/内存/磁盘
- 验收：数据与手工核对一致

### T6.2 任务监控与终止
- 产出：`GET /api/admin/tasks/running`、`GET /api/admin/tasks/queued`、`POST /api/admin/tasks/{id}/kill`（杀进程、FAILED(被管理员终止)、通知用户、写审计）
- 验收：kill 后用户侧看到状态与原因；审计有记录

### T6.3 用户管理
- 产出：`GET/POST /api/admin/users`、`PUT/DELETE /api/admin/users/{id}`、`POST /api/admin/users/{id}/reset-password`、`POST /api/admin/users/{id}/disable|enable`；删除用户级联删任务与文件；全部写审计
- 验收：CRUD/禁用/重置密码行为符合 FR-ADMIN-04/05、FR-AUTH-06、FR-ADMIN-08

### T6.4 系统参数配置
- 产出：`GET/PUT /api/admin/config`：读写 `system_config`（调度器每周期读取，即时生效）；修改写审计
- 验收：调低 max_concurrent 后新任务不再超发

### T6.5 审计日志查询
- 产出：`GET /api/admin/audit-logs`（分页、按动作过滤）
- 验收：T6.2~T6.4 的操作全部可查

## P7 — 定时清理（依赖 P4；FR-CLEAN）

### T7.1 清理任务
- 产出：`scheduler/cleanup.py`：每日扫描 finished_at 早于 retention_days 的终态任务 → 删文件目录 + 删 DB 记录（事务）→ 写运行日志
- 验收：单测用过期任务验证清理彻底；不误删未到期与运行中任务

## P8 — 前端（依赖对应后端模块；全部中文界面）

技术：Vue 3 + Vite + Element Plus + Pinia + Vue Router + axios（JWT 拦截器、401 跳登录）

### T8.1 骨架与认证页
- 页面：登录、注册、注册成功待验证提示、忘记密码、重置密码
- 产出：路由守卫（未登录跳登录页）、token 存储、布局框架（顶部导航 + 通知铃铛）
- 验收：注册→验证→登录→退出 全流程可走通

### T8.2 提交任务页
- 内容：参数表单（从 `GET /api/param-schema` 动态渲染 + 校验）、从模板载入/另存为模板、上传输入文件、提交
- 验收：校验提示正确；提交成功跳任务详情

### T8.3 任务列表与详情页
- 内容：列表（状态标签、时间、耗时，5s 轮询 + 手动刷新、状态过滤、分页）；详情（参数快照只读展示、时间与状态、失败原因、四个文件下载按钮、"复制参数重新提交"按钮、取消按钮）
- 验收：状态随轮询更新；下载可用；取消即时生效

### T8.4 模板管理页
- 内容：模板列表、新建/编辑（复用参数表单）、删除
- 验收：CRUD 完整

### T8.5 用户中心页
- 内容：账户信息（改用户名、改密码）、通知列表（未读高亮、标记已读）
- 验收：FR-AUTH-05、FR-NOTIFY-02 界面可用

### T8.6 管理后台页
- 内容：仪表盘卡片 + 资源使用率、运行中任务表（终止按钮）、等待队列表、用户管理表（搜索/创建/编辑/禁用/删除/重置密码）、系统参数配置表单、审计日志表
- 验收：仅 admin 可见入口；各操作与 API 联调通过

## 关键依赖与风险

1. **T0.1（参数格式规范）是最大外部依赖**：规范不到，T3.1 只能做占位实现，T9.1 无法验收。建议立即向实验室索取。
2. SMTP 账号不到 → T2.1/T2.3 只能用调试收件方式开发，上线前必须就绪。
3. 最大并发 50 与服务器实际核数的关系需在压测时复核（T9.2），必要时调低默认值。
