# DCR_3D 真实参数文件网页管理需求与实现说明

## 1. 数据依据

- 真实样例：`docs/model_DC.dat`
- 参数说明：`docs/DCR_3D_参数文件设置说明.docx`
- Schema 版本：`dcr-model-v1`

平台按固定顺序解析人工边界、VTK 开关、空气域、材料参数、AB 供电源及各源的 MN 观测。空行及 `#` 后内容忽略，支持 E/D 科学计数法。保存会重新生成规范化注释和排版，不保留上传文件的原始注释位置。

## 2. 用户功能

“DCR 参数”页面支持：

1. 读取当前工作区参数；
2. 上传 `.dat` 并加载到网页表单，上传动作本身不保存；
3. 从系统默认参数开始填写；
4. 动态添加、复制和删除材料、AB 源及 MN 观测；
5. 从本人已归档 DCR 任务选择一个真实格式版本并加载；
6. 编辑后保存为当前工作区 `programs/dcr_3d/model_DC.dat`；
7. 下载当前规范化参数文件。

历史版本只作为只读来源。保存历史版本加载结果时，写入当前工作区，不修改 `archives/`。

## 3. 任务语义

DCR 任务不再在提交页单独生成参数。提交时后台将当前参数复制到 `staging/{task_id}/model_DC.dat`，该快照随后不可变。用户在任务排队后继续修改当前参数，不会改变已提交任务。

运行前，任务快照临时覆盖 exe 目录参数；进程结束、失败、取消、超时或重启恢复时，平台将 exe 目录恢复为最新当前参数。归档始终从 staging 读取本次任务参数。

## 4. 一致性与安全

- 用户当前参数同时保存为内部权威镜像和 exe 目录副本；内部镜像解决运行时临时覆盖和后续任务提交的冲突。
- 保存与程序执行/同步共用用户级 PostgreSQL advisory lock。
- PREPARING、RUNNING、ARCHIVING、ARCHIVE_FAILED 期间保存返回 `workspace_busy`。
- 保存必须携带页面加载时的 SHA-256；文件已变化时返回 `stale_revision`，避免两个浏览器标签互相覆盖。
- 上传最大 10 MiB，只接受非空 `.dat` 和 UTF-8/UTF-8 BOM。
- API 不接受服务端路径，历史文件只能通过当前用户所属 Task 记录定位。

## 5. 主要校验

- boundary mode 只能为 1 或 2，VTK 开关只能为 0/1；
- Domain ID 为正整数且唯一，空气域必须出现在材料表；
- rho_x/rho_y/rho_z 必须大于 0；
- 所有浮点参数必须有限，电流不能为 0；
- 每个 AB 源至少一个 MN，A/B、M/N 不得重合；
- geometry mode 只能为 0、1、2、3，自动几何因子模式拒绝零距离和奇异组合；
- 文件计数与实际行数严格一致，不允许尾随 token。

电极是否位于剔除空气后的导电四面体内，本期仍由 DCR_3D 运行时校验。
