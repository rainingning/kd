# Fortran 用户独立工作区与任务版本归档改造 — 需求说明书

- 版本：v1.0（客户需求确认稿）
- 文档类型：现有《需求说明书》的专项变更说明
- 适用项目：Fortran 科学计算平台
- 变更对象：用户目录、计算程序部署、任务暂存、任务执行、版本归档、结果下载、并发限制、程序升级和历史数据迁移

---

## 1. 变更背景

现有平台按任务创建独立目录，并在启动计算程序时把参数文件和输入数据文件的绝对路径作为命令行参数传给 Fortran 程序：

```text
program.exe <参数文件绝对路径> <输入文件绝对路径>
```

客户现有 Fortran 程序中的参数文件名、输入数据文件路径和结果目录均已硬编码。若继续使用原方案，客户必须修改 Fortran 程序的文件路径解析逻辑，客户不接受这一改造方式。

客户提供的正式计算程序由以下两个文件组成：

```text
DCR_3D.exe
libiomp5md.dll
```

其中：

- 参数文件固定为用户根目录下的 `model_DC.dat`；
- 输入数据文件固定为 `mesh/mesh.mphtxt`；
- 结果固定写入用户根目录下的 `Forward_data/`；
- `DCR_3D.exe` 启动时不接收参数文件路径或输入文件路径；
- `DCR_3D.exe` 依赖同目录下的 `libiomp5md.dll`；
- 启动进程时必须将工作目录设置为该用户的根目录。

因此，平台需要从“每任务独立运行目录”调整为“每用户一个固定工作区，同一用户串行执行，任务结束后立即版本归档”。

---

## 2. 变更目标

### 2.1 业务目标

1. 客户无需修改 `DCR_3D.exe` 的任何路径处理代码。
2. 新用户创建时，平台自动为其准备完整、可运行的独立工作区。
3. 同一用户的任务严格串行执行，避免固定文件互相覆盖或多个进程争用同一工作区。
4. 不同用户仍可在全局并发上限内并行运行，因为各用户拥有独立目录和独立程序副本。
5. 每个任务的参数、输入、输出和运行日志在任务结束后立即归档，继续支持历史追溯和版本下载。
6. 下一任务可以覆盖用户固定工作区中的参数、输入和输出，但不得覆盖已归档版本。
7. 支持管理员将新版 `DCR_3D.exe` 和 `libiomp5md.dll` 批量同步到已有用户工作区。

### 2.2 非目标

本次不包含：

- 修改 `DCR_3D.exe` 源码；
- 允许单个用户并行运行多个 Fortran 进程；
- 多计算节点或分布式文件系统；
- 通过 Web 页面上传不受信任的 exe/dll；
- 将旧任务历史迁移为新归档结构（本次确认采用清空旧历史重新开始）。

## 3. 已确认的业务决策

| 编号 | 决策 |
|---|---|
| D-01 | 继续使用 `storage/{user_id}/` 作为用户根目录，不使用可变的用户名作为目录名 |
| D-02 | Fortran 程序来自统一的程序模板目录 |
| D-03 | 开放注册、管理员创建用户以及已有用户初始化都必须复制 exe 和 dll |
| D-04 | 同一用户可以保留多个排队任务，使用任务暂存区避免排队任务互相覆盖 |
| D-05 | 同一用户同一时刻最多运行一个 Fortran 进程 |
| D-06 | 任务进入所有终态时均执行归档，包括成功、失败、超时、用户取消和管理员终止 |
| D-07 | 每次运行前必须清空并重新创建 `Forward_data/`，禁止混入上次遗留结果 |
| D-08 | `Forward_data/` 可能包含多个文件或子目录，按完整目录归档，并以 ZIP 包提供下载 |
| D-09 | 归档版本号采用 UTC 时间戳加任务 ID，例如 `20260808T153012.345Z_task123` |
| D-10 | 旧任务历史在上线切换时清空，不迁移到新归档结构；用户、模板等账户数据保留 |
| D-11 | 每个任务记录程序模板版本，以及 exe 和 dll 的 SHA-256，不在每个任务中重复备份二进制文件 |
| D-12 | `DCR_3D.exe` 正常退出后不会出现 `Forward_data/` 为空的业务情况，平台仍以退出码为主要成功判据 |
| D-13 | 管理员可批量同步新版程序；正在运行的用户延后同步，禁止在进程运行期间替换程序 |

## 4. 术语

| 术语 | 含义 |
|---|---|
| 程序模板目录 | 运维人员放置当前正式版 `DCR_3D.exe`、`libiomp5md.dll` 和版本清单的统一目录 |
| 用户根目录 | `storage/{user_id}/`，同时也是该用户运行 DCR_3D.exe 时的工作目录 |
| 固定工作区 | 用户根目录下会被下一任务覆盖的参数文件、输入目录和结果目录 |
| 暂存区 | 排队任务尚未运行时保存自身参数和输入的目录 |
| 归档区 | 保存任务历史版本的只读目录，后续任务不得修改 |
| 程序版本 | 程序模板清单中声明的版本号，并辅以 exe/dll SHA-256 校验值 |
| 用户执行锁 | 保证同一用户的工作区准备、程序运行、结果归档和程序同步互斥的锁 |

## 5. 目录结构规范

### 5.1 程序模板目录

程序模板目录通过后端环境配置指定，例如：

```text
program_template/
├── DCR_3D.exe
├── libiomp5md.dll
└── program-manifest.json
```

`program-manifest.json` 至少包含：

```json
{
  "version": "1.0.0",
  "exe": "DCR_3D.exe",
  "dll": "libiomp5md.dll",
  "exe_sha256": "...",
  "dll_sha256": "..."
}
```

要求：

1. 后端启动时应检查两个二进制文件和清单是否存在。
2. 实际 SHA-256 必须与清单一致，不一致时模板状态为不可用。
3. 模板不可用时禁止创建新的用户工作区、同步程序或启动新任务，并产生明确告警。
4. 程序模板目录仅由受信任的运维人员更新，普通用户和管理员 Web 页面不直接上传 exe/dll。

### 5.2 用户根目录

每个用户的完整目录结构如下：

```text
storage/
└── {user_id}/
    ├── DCR_3D.exe
    ├── libiomp5md.dll
    ├── model_DC.dat
    ├── mesh/
    │   └── mesh.mphtxt
    ├── Forward_data/
    │   └── ...                     # 当前/最近一次运行输出，会被下一次运行清空
    ├── staging/
    │   └── {task_id}/
    │       ├── model_DC.dat
    │       ├── mesh.mphtxt
    │       ├── stdout.txt
    │       ├── stderr.txt
    │       └── task.json
    └── archives/
        └── {UTC时间戳}_task{task_id}/
            ├── model_DC.dat
            ├── mesh/
            │   └── mesh.mphtxt
            ├── Forward_data/
            │   └── ...             # 完整结果目录，允许多文件和子目录
            ├── stdout.txt
            ├── stderr.txt
            └── task.json
```

### 5.3 固定路径

| 内容 | 固定路径（相对于用户根目录） |
|---|---|
| 计算程序 | `DCR_3D.exe` |
| 动态链接库 | `libiomp5md.dll` |
| 参数文件 | `model_DC.dat` |
| 输入文件 | `mesh/mesh.mphtxt` |
| 结果目录 | `Forward_data/` |

以上名称区分大小写的行为以 Windows 文件系统和 Fortran 程序实际要求为准，平台代码中必须统一使用本文规定的拼写。

### 5.4 归档版本号

归档目录名格式：

```text
yyyyMMdd'T'HHmmss.SSS'Z'_task{task_id}
```

示例：

```text
20260808T153012.345Z_task123
```

要求：

- 时间使用任务归档时的 UTC 时间；
- 精确到毫秒；
- 任务 ID 保证唯一性；
- 数据库保存完整归档相对路径，不依赖运行时重新推导；
- 归档目录一旦完成，不得被后续任务修改。

## 6. 用户工作区生命周期

### 6.1 新用户注册

新增需求编号：`FR-WORKSPACE-01`

用户注册创建数据库用户记录后，平台必须：

1. 创建 `storage/{user_id}/`；
2. 创建 `mesh/`、`Forward_data/`、`staging/` 和 `archives/`；
3. 从程序模板目录复制 `DCR_3D.exe`；
4. 从程序模板目录复制 `libiomp5md.dll`；
5. 计算复制后文件的 SHA-256 并与模板清单复核；
6. 保存该用户当前程序版本和校验结果；
7. 设置合理的文件系统权限，禁止普通 Web 请求任意覆盖 exe/dll。

若任何一步失败：

- 注册接口必须返回明确错误；
- 数据库用户记录和已创建目录必须执行补偿回滚，不得留下半初始化用户；
- 后端日志记录失败阶段和原因；
- 不发送注册成功或邮箱验证成功提示。

用户仍处于 `pending` 状态时也拥有工作区。待验证用户被删除时，其工作区一并删除。

### 6.2 管理员创建用户

新增需求编号：`FR-WORKSPACE-02`

管理员创建用户时必须执行与开放注册相同的工作区初始化流程。不得创建只有数据库记录、没有 Fortran 程序的用户。

### 6.3 用户删除

新增需求编号：`FR-WORKSPACE-03`

删除用户时：

1. 禁止删除有运行中或正在归档任务的用户；
2. 删除该用户的任务、通知和模板等关联数据；
3. 删除整个 `storage/{user_id}/`；
4. 删除失败时不得静默忽略，必须记录并支持重试；
5. 审计日志记录目录删除结果。

### 6.4 工作区自检

新增需求编号：`FR-WORKSPACE-04`

后端应提供工作区自检能力，至少检查：

- 用户目录是否存在；
- exe/dll 是否存在；
- exe/dll SHA-256 是否与用户记录一致；
- `mesh/`、`Forward_data/`、`staging/`、`archives/` 是否存在；
- 是否有足够的读写权限；
- 是否存在异常残留的临时归档目录。

管理员可查看异常用户并触发修复或程序重新同步。

## 7. 任务提交与暂存

### 7.1 提交规则

变更需求编号：`FR-TASK-STAGE-01`

用户提交任务时，平台不得立即覆盖用户根目录中的 `model_DC.dat`、`mesh/mesh.mphtxt` 或 `Forward_data/`。

平台应：

1. 创建数据库任务记录并取得 `task_id`；
2. 创建 `storage/{user_id}/staging/{task_id}/`；
3. 将参数快照序列化为 `staging/{task_id}/model_DC.dat`；
4. 将用户上传的数据文件统一重命名为 `staging/{task_id}/mesh.mphtxt`；
5. 在数据库中继续保存原始上传文件名；
6. 写入初始 `task.json` 元数据；
7. 文件全部写入成功后，任务才能提交为 `QUEUED`。

写入过程中应使用临时文件加原子重命名，防止服务中断后留下被误认为完整的文件。

### 7.2 排队任务隔离

新增需求编号：`FR-TASK-STAGE-02`

同一用户多个排队任务必须分别使用各自的 `staging/{task_id}/`，不得共享暂存文件。

一个排队任务被取消时：

- 不得修改当前用户固定工作区；
- 将该任务暂存的参数和输入直接归档；
- 归档中的 `Forward_data/` 为空目录；
- 保存取消原因和任务元数据；
- 删除原暂存目录。

### 7.3 排队上限

原单用户 `QUEUED` 上限继续保留，默认值仍为 3，可由管理员配置。全局等待队列仍不设置硬性上限。

## 8. 调度与并发限制

### 8.1 单用户运行上限

变更需求编号：`FR-QUEUE-USER-01`

同一用户同一时刻最多只能存在一个正在占用工作区的任务。

“占用工作区”包括以下阶段：

- 准备固定参数和输入；
- 清理结果目录；
- 启动和运行 Fortran 进程；
- 终止进程；
- 归档参数、输入、结果和日志；
- 程序版本同步。

因此，同一用户的实际互斥范围不是只有子进程运行时间，而是从任务开始准备到归档成功并释放用户执行锁为止。

### 8.2 全局并发

变更需求编号：`FR-QUEUE-USER-02`

- 不同用户之间仍可并行运行；
- 全局运行任务数仍受 `max_concurrent_tasks` 限制；
- 同一用户运行上限固定为 1；
- 原 `max_running_per_user` 配置应从可编辑系统配置中移除，或固定为只读值 1，禁止管理员调大；
- 调度器在选择任务时，应跳过当前工作区已被占用的用户，并继续寻找其他可运行用户的排队任务。

### 8.3 并发安全

新增需求编号：`FR-QUEUE-USER-03`

单用户串行限制必须由数据库状态或可跨协程验证的持久化锁保证，不能只依赖进程内字典。

最低要求：

- 并发调度周期不能为同一用户同时启动两个任务；
- 服务重启后不能遗留永久锁；
- 程序同步与任务执行使用同一用户锁；
- 任务归档未完成时，下一任务不能进入固定工作区；
- 即使未来误启动多个后端 worker，也不得突破单用户运行上限。

## 9. 运行前工作区准备

新增需求编号：`FR-EXEC-PREPARE-01`

任务获得用户执行锁后，按以下顺序准备：

1. 再次确认任务仍为可运行状态；
2. 自检用户目录、exe 和 dll；
3. 校验暂存区内 `model_DC.dat` 和 `mesh.mphtxt` 完整存在；
4. 将暂存参数复制到用户根目录临时文件，再原子替换为 `model_DC.dat`；
5. 确保用户根目录下的 `mesh/` 存在；
6. 将暂存输入复制为 `mesh/mesh.mphtxt`；
7. 删除旧 `Forward_data/` 及其全部内容；
8. 重新创建空的 `Forward_data/`；
9. 为 stdout/stderr 日志打开本任务专属文件；
10. 记录本次运行使用的程序版本、exe SHA-256 和 dll SHA-256；
11. 将任务转为 `RUNNING` 并启动程序。

任一步骤失败时：

- 不得启动 `DCR_3D.exe`；
- 任务记录明确的准备失败原因；
- 仍应进入归档流程，保存可用的参数、输入和日志；
- 下一任务必须等本任务归档完成后才能启动。

## 10. Fortran 程序调用规范

### 10.1 启动方式

变更需求编号：`FR-EXEC-COMMAND-01`

调用方式改为：

```text
DCR_3D.exe
```

平台不得再传入参数文件路径或输入数据路径。

等价的进程启动要求：

```text
executable = storage/{user_id}/DCR_3D.exe
cwd        = storage/{user_id}/
arguments  = []
```

### 10.2 DLL 加载

新增需求编号：`FR-EXEC-COMMAND-02`

`libiomp5md.dll` 必须与 `DCR_3D.exe` 位于同一用户根目录。启动前检查 DLL 存在且 SHA-256 与用户当前程序版本记录一致。

### 10.3 标准输出和错误输出

变更需求编号：`FR-EXEC-COMMAND-03`

虽然正式计算结果写入 `Forward_data/`，平台仍必须捕获：

- stdout → 当前任务的 `stdout.txt`；
- stderr → 当前任务的 `stderr.txt`。

stdout 不再等同于结果文件。结果文件的权威来源改为 `Forward_data/`。

### 10.4 状态判定

变更需求编号：`FR-EXEC-COMMAND-04`

- 退出码 0：计算业务状态为成功；
- 非 0：计算业务状态为失败，并记录退出码；
- 超时：杀死进程，业务状态为失败；
- 用户取消运行中任务：杀死进程，业务状态为取消；
- 管理员终止：杀死进程，业务状态为失败，原因“被管理员终止”；
- 进程启动失败：业务状态为失败；
- 上述所有情况均必须先完成归档，再释放用户执行锁。

根据客户确认，正常退出时不存在结果目录为空的业务情况，本期不额外以“结果目录是否为空”改变退出码判定结果。

## 11. 任务归档

### 11.1 归档触发条件

新增需求编号：`FR-ARCHIVE-01`

以下情况全部触发归档：

- `COMPLETED`；
- 程序非零退出；
- 运行超时；
- 用户取消排队任务；
- 用户取消运行中任务；
- 管理员终止；
- 程序启动失败；
- 工作区准备失败；
- 服务重启后的中断恢复。

### 11.2 归档内容

新增需求编号：`FR-ARCHIVE-02`

归档目录至少包含：

1. `model_DC.dat`；
2. `mesh/mesh.mphtxt`；
3. 完整的 `Forward_data/` 目录树；
4. `stdout.txt`；
5. `stderr.txt`；
6. `task.json`。

`task.json` 至少包含：

- 任务 ID；
- 用户 ID；
- 原始输入文件名；
- 参数 JSON 快照；
- 任务提交、开始、结束和归档时间；
- 业务终态；
- 失败或取消原因；
- 退出码；
- 耗时；
- 程序版本；
- `DCR_3D.exe` SHA-256；
- `libiomp5md.dll` SHA-256；
- 归档目录版本号；
- 结果文件数量和总字节数。

### 11.3 归档原子性

新增需求编号：`FR-ARCHIVE-03`

归档必须先写入临时目录：

```text
archives/.tmp_{task_id}_{random}/
```

全部文件复制并校验成功后，再原子重命名为正式版本目录。

正式归档目录出现即表示该归档完整可用。下载接口不得读取临时归档目录。

### 11.4 归档失败

新增需求编号：`FR-ARCHIVE-04`

如果归档失败：

1. 不得释放用户执行锁；
2. 不得启动该用户的下一任务；
3. 工作区保持现场，禁止被覆盖；
4. 任务进入“归档失败/待重试”的可识别状态；
5. 保存 `archive_error`；
6. 后端按退避策略自动重试；
7. 管理员可手工触发重试；
8. 归档成功后，任务才进入最终 `COMPLETED`、`FAILED` 或 `CANCELED` 状态。

建议将状态机扩展为：

```text
QUEUED
  → PREPARING
  → RUNNING
  → ARCHIVING
  → COMPLETED / FAILED / CANCELED

ARCHIVING
  → ARCHIVE_FAILED
  → ARCHIVING（重试）
```

也可以用独立 `archive_status` 字段表达，但必须满足“归档成功前不得覆盖工作区”的业务约束。

### 11.5 归档完成后的工作区

新增需求编号：`FR-ARCHIVE-05`

归档完成后：

- 删除该任务的 `staging/{task_id}/`；
- 固定工作区中的 `model_DC.dat`、`mesh/mesh.mphtxt` 和 `Forward_data/` 可以保留为最近一次运行现场；
- 下一任务运行前将按第 9 章规则覆盖参数和输入，并清空结果目录；
- 所有历史查看和下载必须读取 `archives/`，不得读取可变的固定工作区。

## 12. 历史查询与文件下载

### 12.1 历史记录

- 结果文件数量；
- 结果总大小；

### 12.2 下载类型

变更需求编号：`FR-HIST-ARCHIVE-02`

任务文件下载调整为：

| kind | 下载内容 | 默认下载名 |
|---|---|---|
| `result` | 归档中的完整 `Forward_data/` ZIP 包 | `task_{id}_Forward_data.zip` |

### 12.3 ZIP 生成

新增需求编号：`FR-HIST-ARCHIVE-03`

- ZIP 内保留 `Forward_data/` 下的相对目录结构；
- 不允许通过恶意文件名产生路径穿越；
- 大结果目录应采用流式生成或缓存机制，避免一次性加载到内存；
- 缓存 ZIP 必须受任务保留期清理；
- 普通用户只能下载自己的任务归档；管理员权限沿用现有规则。

## 16. 服务重启恢复

变更需求编号：`FR-RECOVERY-WORKSPACE-01`

服务启动时必须检查：

1. 数据库中残留的 `PREPARING`、`RUNNING`、`ARCHIVING` 或 `ARCHIVE_FAILED` 任务；
2. 用户目录是否存在仍在运行的孤儿 `DCR_3D.exe` 进程；
3. 临时归档目录；
4. 暂存区与数据库任务的对应关系；
5. 用户执行锁是否需要释放或重建。

处理规则：

- 残留 `RUNNING` 任务按“服务重启中断”处理；
- 在确认旧进程已不存在或已被终止后，对工作区现场执行归档；
- 残留 `ARCHIVING` 任务继续归档；
- `ARCHIVE_FAILED` 任务进入重试；
- 归档完成前不调度该用户的新任务；
- 未开始的 `QUEUED` 任务及其暂存区继续保留。

原先“启动时直接把 RUNNING 改为 FAILED”不足以满足本次需求，必须先保护并归档固定工作区现场。

## 17. 定期清理

变更需求编号：`FR-CLEAN-ARCHIVE-01`

原任务保留期继续适用，默认 30 天。清理时删除：

- 数据库任务记录；
- 对应正式归档目录；
- 对应暂存目录；
- 对应 ZIP 缓存；
- 关联通知。

不得删除：

- 用户根目录中的 exe/dll；
- 当前正在准备、运行或归档任务的工作区；
- 未到保留期的归档；
- 无法确认归属的目录（应先告警并由孤儿目录清理流程处理）。

文件删除失败时不得直接删除数据库索引记录，应标记清理失败并重试，避免产生不可追踪的孤儿数据。

## 18. 旧数据切换与迁移

客户确认采用“清空旧任务历史重新开始”，不迁移旧任务到新归档结构。

### 18.1 保留数据

保留：

- 用户账号；
- 邮箱 token（可按有效期正常清理）；
- 参数模板；
- 系统配置中仍适用的配置；
- 管理员审计日志（任务相关旧日志允许保留为审计记录）。

### 18.2 清理数据

清理：

- 全部旧任务记录；
- 全部任务通知；
- 原 `storage/{user_id}/{task_id}/` 任务目录；
- 其他仅属于旧任务历史的文件。

### 18.3 切换步骤

1. 停止后端服务和调度器；
2. 确认没有仍在运行的 Fortran 进程；
3. 完整备份 PostgreSQL 和 `storage/`；
4. 记录备份位置和校验值；
5. 执行数据库迁移；
6. 清空旧任务及任务通知；
7. 清理旧任务目录；
8. 为每个已有用户初始化新目录结构；
9. 复制并校验 exe/dll；
10. 对所有用户执行工作区自检；
11. 只有全部关键检查通过后才重新启动服务；
12. 使用正式 DCR_3D.exe 执行至少一次端到端验收。

### 18.4 安全要求

- 清空历史属于不可逆操作，必须在管理员二次确认后执行；
- 没有成功备份不得执行清理；
- 迁移脚本必须可重复运行或能识别已完成步骤；
- 迁移过程输出用户级成功/失败清单；
- 任一用户初始化失败不得被静默跳过。

## 19. 异常处理

| 场景 | 处理要求 |
|---|---|
| 程序模板缺少 exe 或 dll | 禁止注册初始化、同步和新任务启动，管理员告警 |
| 模板 SHA-256 不一致 | 模板标记不可用，禁止同步 |
| 用户目录缺少 exe/dll | 任务不启动，工作区标记异常，可由管理员同步修复 |
| 暂存参数或输入缺失 | 任务失败并归档现有内容 |
| 固定文件覆盖失败 | 任务失败，不启动程序，保留现场 |
| `Forward_data` 清理失败 | 任务失败，不启动程序，防止旧结果混入 |
| 程序启动失败 | 保存 stderr/异常信息并归档 |
| 任务超时 | 杀死进程，等待退出，归档现场后记失败 |
| 用户取消 | 杀死进程或取消排队，归档后记取消 |
| 管理员终止 | 杀死进程，归档后记失败并通知用户 |
| 归档失败 | 锁定该用户工作区，自动/手工重试，不启动下一任务 |
| 程序同步时用户开始运行 | 通过同一用户锁保证二者只有一个成功进入临界区 |
| ZIP 生成失败 | 不影响原始归档，向用户提示并允许重试 |
| 磁盘空间不足 | 禁止启动可能覆盖现场的新任务，管理员告警 |

## 20. 非功能性要求

### 20.1 一致性

- 同一用户任何时刻最多一个任务占用固定工作区；
- 归档成功前不允许下一任务覆盖固定文件；
- 历史下载只读取不可变归档；
- 程序同步与任务运行互斥。

### 20.2 可靠性

- 文件复制采用临时文件加原子替换；
- 归档采用临时目录加原子重命名；
- 关键文件计算 SHA-256；
- 归档和同步失败可重试；
- 服务重启后能够保护并归档中断任务现场。

### 20.3 性能

- 不同用户仍支持全局配置范围内的并发；
- 同一用户严格串行；
- 大结果目录 ZIP 不得一次性加载到内存；
- 文件复制、哈希和压缩不得阻塞 FastAPI 事件循环，应放入线程池或独立后台执行单元。

### 20.4 安全

- 普通用户无权下载或访问其他用户工作区；
- API 不接受用户指定服务端相对或绝对路径；
- 所有路径由 `user_id`、`task_id` 和平台规则生成；
- 防止 ZIP 路径穿越；
- exe/dll 只允许从可信模板同步；
- 程序同步、修复和归档重试必须审计。

### 20.5 可观测性

日志至少记录：

- 用户工作区创建和校验；
- 任务暂存；
- 工作区准备；
- 程序版本和哈希；
- 进程启动和退出；
- 归档开始、成功、失败和重试；
- 程序同步；
- 历史清理；
- 磁盘空间不足。
